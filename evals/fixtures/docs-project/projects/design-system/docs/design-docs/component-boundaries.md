# コンポーネント分割基準

`docs/DESIGN.md`の「境界」を実例で補う詳細文書である。現在有効な原則そのものは`DESIGN.md`が持つ。

## 分割する条件

- 1部品が2つ以上の呼び出し文脈で別々の状態を要求する。
- 表示分岐が3つを超える。

## 分割しない条件

- 見た目だけが違い、状態と責務が同じ。
- 1画面でしか使われておらず、再利用の見込みがない。

## 実例

- `Button`と`IconButton`は分割した。ラベル有無で必要な状態が変わるため。
- `Card`と`ElevatedCard`は分割しなかった。差分がtokensの値だけだったため。
